   `powerbi/MIZAN Control Tower Model.SemanticModel/definition/tables/*.tmdl`, and `docs/design/DATA_NOTES.md`.
2. **The existing Command Center stays exactly as it is.** Do NOT modify, move, rename or delete anything under
   `apps/command-center/`, `command_center/`, `scripts/build_command_center.py` or the `powerbi/` folder. The new
   app lives **alongside** it in a new folder: `apps/control-tower-v2/` with its own `rayfin/rayfin.yml`

   building and deploying independently. If you think a change outside `apps/control-tower-v2/` is needed, stop and

3. **No typed-in numbers. Ever.** Every figure on screen comes from (a) live DAX over the semantic model
   *MIZAN Control Tower Model* through the Rayfin connector, or (b) the exported proof data
   (`apps/command-center/src/command-center/proof.json` / `snapshot.json`, generated by
   `scripts/build_command_center.py`). Copy those two files into the new app with a small `scripts/sync-data.mjs`
   (read-only on the source) and add a test that the copies are byte-identical to the source. Live failures fall

5. **Money:** never float. Query money as integer halalas (see the existing `.dax` files), hold it as `BigInt` in

6. **Honesty language is part of the design** (from HONESTY.md): synthetic data, not ZATCA-certified, mock Fatoora,

8. **Deploying:** `npx rayfin up` creates a new Fabric item. Show me the dry run and ask before running it.

9. **Work in phases** (section 9). After each phase: `npm run lint`, `npx tsc -b`, `npm test` green, a screenshot

## 2. The story the dashboard tells (domain)

MIZAN (ميزان, "balance/scale") proves that every assessed halala balances across **four systems**:
**order/capture -> ZATCA e-invoice -> bank settlement -> GL**. Organise the whole UI around that balance:

- **Four-way reconciliation:** key spine (no dropped rows), halala-zero variance (bank AND GL must be 0.00),
  `IN_TRANSIT` expectation rows for days whose bank file has not arrived (shown hatched as "Awaiting bank file - not
  assessed", never as balanced), quarantined SAR and unclassified events counted.
- **dbt circuit breaker:** published run PASS vs candidate run FAIL (the planted halala defect); a "candidate run"
  toggle tilts the scale and stamps UNBALANCED with the exact SAR from the data.
- **ZATCA Phase-2 chain:** ICV sequence, PIH hash links from the genesis PIH, chain states (SUBMITTING, CLEARED,
  REPORTED, ACCEPTED_WITH_WARNINGS, CONFIRMED_REJECTION, AUTH_HOLD, UNKNOWN_OUTCOME), retries with identical bytes,
  per-EGS device health, 24h reporting window for B2C.
- **MDM golden records:** Arabic/English spellings converging to one golden ID; the brothers who must not merge.
- **PDPL crypto-shredding:** right-to-erasure timeline (token link removed, DEK shredded, VACUUM, restore guard
  re-shreds), legal hold classes TAX / SAMA / CONSENT, tax totals unchanged after erasure.
- **NDMO classification & data quality:** tiers per column, 6 quality dimensions vs thresholds, residency gate (and
  the honest note that the trial capacity is UAE North).
- **Lineage:** source -> Bronze -> Silver -> Gold -> app, column coverage, OpenLineage/Marquez.
- **Streaming fraud rules:** Eventstream/KQL velocity and mule-ring alerts, SLA breach (historical replay, labelled).
- **Card-scheme dispute monitor:** ratio alone flags many, ratio + count floor flags one; show why.

## 3. Visual direction: "Mizan" - a Saudi financial control tower

- **Concept:** the balance scale. The hero is a living scale whose two pans are *what was sold/invoiced* and *what
  was settled/posted*; it comes level when variance is 0.00 and tilts (with a soft spring) when a filter or the
  candidate run shows a break. Equilibrium ring and "BALANCED - N assessed MID-days" stamp come from data.
- **Mood:** calm authority, like a central-bank operations room at night. Deep ink-navy surfaces, brushed **Saudi
  gold/brass** as the brand accent (the scale), subtle geometric Islamic star-lattice pattern at very low opacity in
  hero backgrounds, crisp hairline borders, glass panels. Not neon, not gamer.
- **Use a token-based design system** (CSS variables, defined before any component, in `src/design/tokens.css`):
  - Color: brand (gold 50-900), neutral ink scale, and **semantic roles separate from brand**: success (reconciled /
    pass only), warning (in transit / estimated / awaiting), danger (break / rejection / breach), info (proof run /
    replay), neutral (not assessed). Charts never use a semantic color for a non-semantic meaning. Captures neutral,
    refunds violet, fees grey, as in the current app. A categorical chart palette checked for color-blind safety.
  - **Layered dark palette:** 4 surfaces (background, card, raised, overlay) + 1px subtle border; no pure black, no
    pure white text. Matching light theme (warm paper, ink text, same accent).
  - Type: IBM Plex Sans + IBM Plex Sans Arabic (or equivalent pair with matched x-height), a mono for hashes/IDs,
    fluid type scale; **tabular numerals** everywhere numbers appear.
  - Spacing (4px base), radius, shadow/elevation (soft layered shadows, inner glow, **gradient borders on hero
    cards**), z-index, blur, and **motion tokens** (durations 120/200/320/600ms, easings standard/emphasized/spring,
    stagger 60ms).
- **Dark/light toggle** with a smooth theme cross-fade (View Transitions API where supported, CSS fallback),
  persisted, respecting `prefers-color-scheme` on first load.
- **Noise/grain overlay** at 2-3% opacity; custom scrollbars and `::selection` in the brand gold.
- **Saudi context:** SAR everywhere, Asia/Riyadh time, Gregorian + Hijri dual dates (Hijri from `dim_date_saudi`),
  Fri-Sat weekend shading, Ramadan band, government payday marker, **full EN/AR toggle with RTL layout** (mirror
  layout, sidebar on the right; numbers, IDs, hashes and charts stay LTR with Western digits; use logical CSS
  properties `margin-inline`, `inset-inline`). Watch the known bug: `direction: ltr` on a flex row also flips its
  packing edge - test the hero counter in RTL. Arabic strings live in one i18n file, written as `\uXXXX` escapes
  per the project rule.

## 4. Layout and navigation

- **Bento grid** home with **one dominant hero card** (the scale + headline KPIs) and varied card sizes (2x2, 2x1,
  1x1, 1x2), responsive down to tablet and phone.
- **Collapsible icon rail sidebar** (Lucide icons only, labels on expand, tooltips when collapsed), **breadcrumbs**,
  **sticky glass-blur header** with: global date range, compare-to toggle, EN/AR, theme, role switch
  (Finance / Tax / Data office / All staff, mirroring `GOLD_ACL` as the current app does), data freshness pill
  (live/snapshot + as-of), command palette trigger.
- **Command palette (Ctrl/Cmd+K):** jump to any page/widget, search MID, EGS, city, ICV, invoice UUID, golden ID;
  actions (toggle theme, Arabic, candidate run, focus mode, export, follow one riyal); recent items; keyboard-first.
- **Saved views** (named filter + layout presets, localStorage, shareable via URL query string) and a
  **customizable drag-and-drop widget layout** with reset-to-default.
- **Focus mode:** any chart expands to full screen with a shared-element transition, keeps its filters, Esc closes.
- **Pages** (each a bento of its own):
  1. **Overview** - hero scale, four-system balance strip, KPI row, AI insight card, alerts feed, mini map.
  2. **Reconciliation** - four-way waterfall (captures -> refunds/disputes -> fees -> expected net -> bank paid ->
     in transit -> variance 0.00), Sankey money flow, 121-merchant x day **halala heatmap** (hatched not-assessed
     cells), MID-day drill-through panel showing all four legs, circuit-breaker panel.
  3. **ZATCA e-invoicing** - chain tape (ICV blocks linked by PIH, animated), state funnel/flow, outcome bar,
     per-EGS device cards with sparklines, retries and corrections, B2C 24h window rings, ZATCA SDK result panel.
  4. **Payments & fees** - scheme/method treemap, fee rate bps bullet charts vs median, goal-vs-actual bars, daily
     captures area with annotations.
  5. **Merchant risk** - dispute scatter (ratio vs volume, count floor and ratio lines), 71-vs-1 explainer, radar
     per merchant, streaming alerts timeline (historical replay), gauge for portfolio dispute ratio.
  6. **Data trust** - NDMO scorecard radial rings, DQ dimensions vs threshold bars, classification tiers, lineage
     graph (Gold column coverage), quarantine reasons, dbt/Fabric run status.
  7. **Privacy (PDPL)** - erasure timeline with success-check animations, legal hold classes, "tax totals unchanged"
     proof.
  8. **Identity (MDM)** - golden-record convergence animation (Arabic + English spellings), hard-negative card.
  9. **Saudi calendar** - Hijri/Gregorian **heatmap calendar** of captures, Ramadan, weekends, paydays.
  10. **Pipeline** - data life cycle (sources -> Bronze -> Silver -> Gold -> app), Airflow run timings, Spark skew
      race; every box jumps to its page.
  11. **Follow one riyal** - one capture traced through till -> ZATCA invoice -> bank line -> GL, with joining keys,
      using `proof.trace` (and its "selected by rule" note).

## 5. KPI and data elements (use all of these where they fit the data)

- **Animated count-up numbers** with **delta chips** (`▲ 12.4% vs prior period`, colored by meaning, with an arrow
  and sign, not color alone). Compare period comes from the compare-to toggle; if the window has no prior period in
  the data, show "no comparison period" rather than inventing one.
- **Sparklines**, **bullet charts**, **radial progress rings**, **gauge meters**, **goal vs actual bars with target
  markers** (thresholds from the data: NDMO `threshold_pct`, dispute floors from proof data).
- **Heatmap calendars**, **treemaps**, **Sankey flows**, **funnel charts** (ZATCA states), **radar charts**
  (merchant risk profile, NDMO dimensions).
- **Waterfall charts for variance**, **cohort tables with color-scale cells** (merchants by first-capture week x
  day, or EGS x day acceptance).
- **Smart annotations** on timelines: spikes, anomalies, Ramadan start, paydays, the 2026-03-03 missing bank file,
  the ICV 102 incident, SLA breach - each derived from data, with a tooltip explaining it.
- **AI insight card**: a plain-language "what changed and why" summary for the current filters. Build it as a
  **deterministic rule engine over the query results** (templates such as "Bank variance stayed at SAR 0.00 across
  N assessed MID-days; M days are awaiting the bank file"), where every number in the sentence is bound to its
  source field and hovering it highlights the source widget. Label it "Generated from the figures on this page".
  Do not call a language model for it (HONESTY rows 14-15).
- **Alerts / exceptions feed**: breaks, rejections, AUTH_HOLD, quarantine, programme merchants, SLA breach; each
  with severity icon + label, timestamp in Riyadh time, and click to drill.
- **Data freshness & SLA**: `last_source_arrival_at` per source, age badges.
- **Top-N / bottom-N tables** with inline bars, virtualized when long.

## 6. Motion and micro-interactions (animate every surface, tastefully)

Use framer-motion for UI and layout, GSAP for timeline storytelling, d3 transitions for charts, Three.js only for
the hero scale. All durations/easings from motion tokens.

- **Page load:** staggered entrance, each card offset ~60ms, fade + 8px rise + slight blur-in; hero first.
- **Hero:** the scale assembles, pans fill (captures pan first, bank pan at T+1), beam settles level with a damped
  spring; gold particles flow from pan to pan along the four-system path; equilibrium ring pulses once.
- **Charts:** bars grow from zero, line paths trace in (stroke-dashoffset), areas wipe in, donut/rings sweep, Sankey
  links flow with moving particles, treemap tiles scale in, heatmap cells ripple in diagonally, waterfall steps drop
  in sequence, gauges needle-sweep with overshoot, radar polygons morph.
- **Numbers:** count-up on first view; **smooth number morphing** (digit roll) when filters change; delta chips pop.
- **ZATCA chain tape:** blocks slide in and link with a drawn hash line; a rejected block shakes once and turns
  danger; retry shows "identical bytes" with a match animation.
- **PDPL:** keys dissolve to ash on shred, **success checkmark** draws on each completed step.
- **MDM:** name cards drift and snap into the golden record with a magnetic pull.
- **Cards:** hover lift (translateY -2px, shadow up a level), gradient-border sheen sweep on hero cards,
  **magnetic buttons**, press scale 0.98.
- **Tooltips:** animated, follow the cursor with spring smoothing, flip at edges, show full SAR, Hijri + Gregorian.
- **Loading:** **shimmer skeleton loaders** shaped like each widget; **animated empty states** (a small scale icon
  gently rocking, "No data for these filters" + a Clear filters button); error states with retry.
- **Drill:** **shared-element transitions** from a card into its detail view (layoutId), breadcrumb back-trail
  animates back.
- **Filters:** chips animate in/out; cross-filtered visuals dim non-matching marks with a 200ms fade.
- **Ambient:** slow gradient drift and the faint star-lattice shimmer in the hero, under 0.5 fps of visual change.
- **Theme and language switch:** cross-fade; RTL switch animates the rail to the other side.
- **Reduced motion:** with `prefers-reduced-motion` (and an in-app "Reduce motion" setting), disable ambient
  motion, particles, count-ups and parallax; show final states instantly; keep only opacity fades under 150ms.
  Pause off-screen animations (IntersectionObserver) and the Three.js loop when the tab is hidden.

### 6b. Cinematic motion graphics (the "wow" layer)

Treat key moments like a film title sequence: GSAP timelines (ScrollTrigger-style scroll scrubbing built with
IntersectionObserver if the plugin is not in the pinned package), Three.js for the hero, SVG/canvas for the rest.
Every frame still shows real figures from the data.

- **Opening sequence (first visit, about 6s, skippable with any key, "Replay intro" in the palette):** black-to-ink
  fade, the star-lattice pattern draws itself line by line in gold, the word MIZAN / ميزان resolves out of it, the
  lattice folds into the balance scale, the camera dollies in with shallow depth-of-field, the pans fill and the beam
  settles level, then the bento grid assembles around it card by card. Shown once per session.
- **Camera language in the hero:** slow orbit on idle, parallax tilt that follows the pointer, rack-focus blur
  between foreground KPIs and the scale, soft volumetric light rays and a gold rim light on the beam, a subtle bloom
  pass kept cheap (or a CSS glow fallback on weak GPUs).
- **Kinetic typography:** headline KPIs enter with a masked line reveal and letter tracking that tightens into
  place; Arabic headlines use a right-to-left mask wipe.
- **Scroll-scrubbed chapters:** on each page, scrolling drives a pinned story beat, for example on Reconciliation the
  money physically flows from the till, splits off refunds and fees, crosses to the bank, and lands in the GL, with
  the running total morphing in sync, ending on a stamped "0.00".
- **Data particles with meaning:** one particle = a fixed SAR amount from the data, so density is honest; particles
  stream along the Sankey and the map routes (store -> acquirer hub -> settlement bank), turning amber while in
  transit and gold on settlement.
- **Event "moments":** when the candidate run is switched on, a short cinematic beat plays: time slows, the scale
  tips, a red scanline sweeps the heatmap and locks onto the broken MID-days, and the UNBALANCED stamp hits with a
  small camera shake. ZATCA ICV incident replay plays as a timeline with a scrubber, play/pause and 0.5x / 1x / 2x.
- **Transitions between pages:** directional wipes along the four-system path (order -> invoice -> bank -> GL),
  with a gold light streak leading the incoming page; morph the active rail icon into the page header.
- **Map scene:** a 2.5D KSA map that tilts in, cities rise as glowing columns sized by captures, arcs draw between
  stores and banks.
- **Loop-ready "showcase mode":** a self-running reel that cycles pages with their best animation for a lobby
  screen or a LinkedIn screen recording, with captions and the provenance label always visible.
- **Sound (off by default):** optional, very subtle UI ticks and a low tone when the scale settles, with a mute
  toggle in the header. Ask before adding any audio asset.
- **Guardrails:** cinematic layers never block reading a number for more than a second, never animate a value
  that is not in the data, pause when the tab is hidden, drop to a static poster frame under reduced motion, and
  degrade gracefully (check `navigator.hardwareConcurrency` / WebGL availability and fall back to SVG).

## 7. Interaction design

- **Cross-filtering:** clicking a chart segment (heatmap cell, EGS bar, treemap tile, Sankey node, calendar day,
  scatter point, city) filters every other visual on the page; use `@microsoft/fabric-interaction-manager` /
  `useQueryFactoryTarget` where it fits, and validated predicates like `filters.ts` (no DAX injection - copy its
  approach and tests).
- **Drill-down** (month -> day -> merchant -> MID-day), **drill-through** (MID-day detail with all four legs, EGS
  detail, merchant risk detail), **breadcrumb back-trail**.
- **Date range presets** (whole window, last 7 days, Ramadan, pre-Ramadan, custom, Hijri month), **compare-to**
  toggle, **multi-select chips** (merchant, city, EGS, scheme, invoice flow, outcome, assessed/not assessed).
- **Hover-to-highlight:** hovering a series/legend item dims everything else.
- **Right-click context menus** on marks: drill through, filter to this, exclude, copy value, copy DAX, explain.
- **Export:** PNG (per widget), PDF (current page, branded header with provenance and as-of), CSV (the exact rows
  behind a widget). Ask before adding a library for PDF; prefer the browser print pipeline with a print stylesheet.
- **Keyboard:** full navigation, visible focus rings, shortcuts overlay on `?` (Ctrl+K palette, `F` focus, `T`
  follow one riyal, `B` candidate run, `L` Arabic, `D` theme, `1`-`9` pages).
- **Presenter / story mode:** a guided 5-chapter tour with captions for demos (chrome hides, auto-advances,
  pausable).

## 8. Polish, accessibility, performance

- One icon set only: **Lucide** (already installed). Never mix styles.
- **Tabular numerals and right-aligned numbers** in tables and KPI blocks; compact formatting (`1.2M`, `SAR 22.39M`)
  with full value in tooltip; truncation with tooltips for long IDs/hashes (middle-ellipsis for hashes).
- **Real empty, error and loading states for every widget** (one shared `WidgetState` component).
- **WCAG AA contrast** in both themes (check with a contrast script), patterns/hatching and labels in addition to
  color (not-assessed = hatch, break = icon + label), ARIA labels and a visually hidden data table for every chart,
  focus trap in palette and focus mode, `lang="ar" dir="rtl"` set correctly.
- **Performance:** lazy-load heavy pages and Three.js (code-split per page), virtualize long tables (121 merchants x
  days, 25k documents), cache query results (the template has `src/lib/query-cache.ts`) keyed by filter set,
  debounce filter changes, keep DAX at the minimum grain needed, target LCP < 2.5s on the Fabric host and 60fps
  animations (transform/opacity only).
